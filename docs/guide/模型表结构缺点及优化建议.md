🔴 最高风险：没有数据库迁移
你的 init_db()：

复制
async def init_db():
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
create_all 只会新建不存在的表，不会改已有表的结构。现在你所有表都还活着，是因为每次都重新建库。但如果你：

给 Post 加一个 reading_list 字段
给 Dex 加 created_at
加一张新表
……create_all 完全不管你。未来修改表结构，你有三个选择：

用手删数据库文件重新建（现在还能忍，上了线就完了）
手动写 ALTER TABLE（容易出错）
上 Alembic（正道）
建议： Alembic 对 FastAPI + SQLAlchemy async 是标配，接入成本不高。核心就这几步：

复制
pip install alembic
alembic init alembic
# 配置 alembic/env.py 连你的 DATABASE_URL
alembic revision --autogenerate -m "init"
alembic upgrade head
之后每次改 model → alembic revision --autogenerate -m "加了xxx" → alembic upgrade head。这才是长期维护的底子。

🟠 中风险：几个字段定义小毛病
① DexGenre.color 的 nullable 冲突

复制
# dex_genre/model.py
color: Mapped[str | None] = mapped_column(String, nullable=False)
#                          ↑ Optional                 ↑ 但又说不能为空
类型注解说「可能有 None」，但数据库约束说「NOT NULL」。你创建 genre 时如果不传 color，Python 层面能过（塞 None），但 SQLite 会报 IntegrityError。要么统一 nullable=True，要么去掉 | None。

② PostTag.slug 可空，但其他 slug 不可空

复制
# post_tag/model.py
slug: Mapped[str | None] = mapped_column(String, nullable=True)

# post_category/model.py
slug: Mapped[str] = mapped_column(String, nullable=False, unique=True)
一样的标签体系，一个可空一个不可空，以后前端做「根据 slug 获取」时，有些 tag 没有 slug 会 404。最好统一。

③ Post.cover_image 可空，Dex.cover_image 不可空

复制
# post/model.py
cover_image: Mapped[str | None] = mapped_column(String, nullable=True)

# dex/model.py
cover_image: Mapped[str] = mapped_column(String, nullable=False)
Post 没图也能过，Dex 没图就报错——如果用户上传文章时没有选封面图，Post 没事，Dex 就要报 500。要么 Dex 也放开 nullable，要么前端表单都做必填校验。

④ PostCategory.description 是 String 不是 Text

复制
description: Mapped[str] = mapped_column(String, nullable=True)
SQLite 里 String 默认是 VARCHAR，如果 description 一长就会被截断。Post 和 Media 的类似字段用的是 Text，这里不一致。

🟡 低风险但值得改进
⑤ Dex 缺少时间戳

复制
class Dex(Base):
    # ...一堆字段...
    # ❌ 没有 created_at / updated_at
Post 有 created_at / updated_at，同为主内容实体的 Dex 却没有。想做「最近添加的条目」「按时间排序」就没法了。建议加：

复制
created_at: Mapped[datetime] = mapped_column(DateTime, default=_utcnow)
updated_at: Mapped[datetime] = mapped_column(DateTime, default=_utcnow, onupdate=_utcnow)
⑥ Dex.start_date / finish_date 是字符串

复制
start_date: Mapped[str | None] = mapped_column(String, nullable=True)
finish_date: Mapped[str | None] = mapped_column(String, nullable=True)
存 "2026-01" 没问题，但你要是想按时间范围筛选、做统计图表，字符串查询效率低而且容易有格式不一致。如果真有查询需求，改成 Date 类型最好。

⑦ 缺少 JSON 扩展字段（除了 Media）

Media 有一个很聪明的设计：

复制
meta_data: Mapped[dict] = mapped_column(JSON, default=dict)
Post 和 Dex 没有。以后如果想加「Post 的自定义元信息」（比如原文链接、是否翻译、系列名……），就得改 model 加 migration。如果现在在 Post 和 Dex 里也放一个 meta_data: dict = mapped_column(JSON, default=dict)，后面很多事情就「不改表也能加字段」了。

⑧ hard delete 没有回收站

所有删除都是 await db.delete(obj) 真的删了。如果未来想做「最近删除」「回收站」，所有模块都要大改。如果现在就有这种预感，可以加一个 deleted_at: datetime | None 做成软删除。但这事不急，等你真有回收站需求再说。
