## 当前现状

这个项目目前是**彻底的单用户架构**：

- 后端没有任何 `User` 模型
- 没有任何认证/鉴权（JWT、session、密码什么都没有）
- `/admin` 页面任何人只要知道 URL 就能访问，随便增删改
- 每篇文章、图鉴、媒体都没有「所属用户」的概念
- 数据库（SQLite）所有数据都是公开共享的

### 3️⃣ 权限粒度设计（可选）

最简单的做法——**三种角色**：

```
admin   → 全部权限（超级管理员）
editor  → 可以管理内容，不能管理用户
viewer  → 只能读，不能写（凑数的，一般不会用到）
```

### 4️⃣ 不做也行的地方（不强迫改）

- 现有的内容**不需要加 `user_id`**，作为系统初始管理员的数据就行
- 注册接口**建议关闭或加邀请码**（否则谁都能注册），多用户其实指"管理员+编辑者"
- 文件上传路径不需要变

## 实际实现时的贴士

1. **JWT 用 `python-jose` + `passlib[bcrypt]`**，轻量无侵入
2. **token 存 `localStorage`**，Vite proxy 加 `Authorization` header
3. **`get_current_user` 做成 FastAPI 的 `Depends`**，一行就能保护路由：

```python
@router.post("", response_model=PostResponse, status_code=201)
async def create_post(
    data: PostCreate,
    db: AsyncSession = Depends(get_db),
    current_user: User = Depends(get_current_user)  # ← 这行
):
    if current_user.role not in ("admin", "editor"):
        raise HTTPException(403, "权限不足")
    post = await crud.create_post(db, data, user_id=current_user.id)
    ...
```

4. **Dex 和 Media 同理**，分享同一个 `Depends(get_current_user)`
