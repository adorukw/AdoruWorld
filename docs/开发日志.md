### 问题及解决方案

1. **问题**：我不清楚如何编写后端数据的导入导出功能，不知道是在前端实现还是在后端用脚本实现，也不知道导入导出的文件该用什么格式
   **解决方案**：我使用openclaw来解读我的整体项目代码，给我解答，通过编写后端脚本来实现数据导入导出功能，并使用JSON+ZIP格式来打包数据

2. **问题**：我还没有部署项目到服务器，忘记了生产环境的url和Nginx之类的如何配置了
   **解决方案**：我用openclaw总结了一个部署文档，我按照文档上的步骤部署了项目到服务器，并配置了Nginx

3. **问题**：前端打包的时候遇到ts报错“声明变量未读取”
   **解决方案**：把没用到的变量全都删了，然后重新打包前端

4. **问题**：遇到vite最新版打包的时候的lightningcss严格检查css报错，根本原因是引用的第三方像素库有问题
   **解决方案**：还没搞懂怎么配置，就先用
   `typescript
build: {
    // minify: 'terser',      // 全部用 terser
    // cssMinify: 'terser'    // CSS 也用 terser
    cssMinify: false,  
},
`
   来取消压缩css

5. **问题**：我不知道如何在服务器持久启动后端服务
   **解决方案**：有一种方法是通过创建`/etc/systemd/system/adoruworld.service`服务来实现，但我决定使用
   `bash
   screen -S adoru-backend  
    cd /home/adorukw/project/AdoruWorld/server  
    python3 run.py

   # Ctrl+A, D 断开

   # 回来：screen -r adoru-backend

   `

6. **问题**：Nginx没权限直接读取静态文件
   **解决方案**：直接运行`chmod o+x /home/adorukw `

7. **问题**：前端部署好之后进去只有背景
   **解决方案**：发现是前端路由的createWebHistory()没有加上`/blog/`前缀

8. **问题**：端点击导航栏路由跳转的时候,url不会带上/blog/前缀
   **解决方案**：原因是前端跳转链接用了原生的a标签并且没有加上前缀，需修改成`<router-link :to="item.path">`，这样前端路由会自动加上前缀

9. **问题**：前端请求uploads文件时不带有/blog/前缀
   **解决方案**：原因是前端使用的uploads文件url是后端返回的，但是后端并没有加上前缀，端的 coverImage 返回的是服务端视角的路径，不是客户端视角的路径。比较规范的做法是后端返回完整的URL（带上部署的子路径），或者前端在 BASE_API_URL 里也处理图片路径。
